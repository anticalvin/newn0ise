# Open-source integration report

Facts checked on 2026-11-17 (npm registry and GitHub). "Tested" means we ran it in the 3D page in the in-app browser; no physical phone.

| Project | Existing support | Decision | Result |
|---|---|---|---|
| **Manifold** (Apache-2.0, v3.5.5, 80 KB JS + 540 KB wasm, maintained) | None before | **Integrated** | Scene tab → Combine shapes: Union, Cut, Overlap, keep-originals option, "+ Cutter box / cylinder". Also `n0.run({cmd:'boolean'})` for agents. Tested: subtract of a 2×2×2 cube and a 1×3×1 cylinder gave volume 6.434 (ideal 6.429, the cylinder is a polygon); union and undo work; originals are hidden, not deleted, and Undo restores them; project save and reopen keep the combined solid (new `geo` item). Limit: inputs must be closed solids; open meshes fail with a plain message. Loads from the pinned CDN on first use. |
| **three-mesh-bvh** (MIT, 0.9.17 pinned, maintained) | Shipped only for the path tracer; picking was a plain raycast | **Improved** | `src/bvh.js` builds a tree for meshes of 20,000+ triangles when they are added (lazy import). Measured on a 74,420-triangle mesh: 2.33 ms per ray before, 0.0135 ms with the tree (about 170× faster); one-time build 0.8 s. Sculpting clears the tree on the mesh it edits. Limit: build time grows with triangle count (blocks the page); not yet moved to a worker. |
| **glTF Transform** (MIT, 4.5.1, maintained) | None | **Integrated** (opt-in) | Export → Scene → smaller GLB (dedup, prune, weld, quantize; `src/optimize.js`, loaded on demand). Tested: a 3.15 MB generated sphere became 0.46 MB (6.8×) in 26 ms; the Character GLB went 4.23 MB to 2.44 MB with skin and 16 morph targets intact (re-parsed). Falls back to the normal GLB if it can't load. Uses KHR_mesh_quantization, which current three.js and Blender read. The normal export is unchanged. |
| **Three.js editor** (MIT) | n0ise has its own editor | **Studied** | Lessons applied: undo that records add (done, `Undo` now removes an added shape); command-style scene API (kept). Still to do: a hierarchy panel with grouping and per-object visibility and lock. Not copied. |
| **three-gpu-pathtracer** (MIT, 0.0.27 pinned) | Already in Material preview and Render scene | **Audited, small fix** | Loads and switches on; here it stayed at 0 samples (software GL in this environment) so quality could not be judged. Added a progress label ("N samples", "Done", or "Too slow here. Turn Path trace off") and a safe getter for the sample cap. |
| **three.js TSL / node materials** (MIT) | n0ise has its own `nodemat.js` graph that bakes to maps | **Research only** | TSL node materials target `WebGPURenderer`; n0ise uses `WebGLRenderer` and a custom compositor. Moving would change rendering. Not prototyped. Recommendation: keep `nodemat.js`, use its serialisable graph as the shared data for a future visual editor. |
| **LiteGraph.js** (MIT, last push 2024-08) | None | **Research only** | Canvas node editor with serialisation. Older and canvas-based; mobile touch support is unverified. Not prototyped. A small purpose-built touch graph over `nodemat.js` is likely cheaper than adopting it. |
| **OSM Buildings** (licence unclear, last push 2021) | None | **Research only** | Treat as a reference. Smallest viable path: fetch building footprints and heights from the OpenStreetMap Overpass API (data is ODbL, needs attribution), extrude them with the `src/build.js` wall and floor model, export as a world. No code from OSM Buildings. |
| **Terrain3D** (MIT, Godot) | `src/sculpt.js` brushes on meshes | **Reference only** | Useful ideas: heightmap in chunked regions, brush falloff curves, texture splat map per region, LOD by distance. Plan: heightfield object type with the existing brush UI and falloff; chunks of 64×64 for low-end phones. |
| **Blender Geometry Nodes** (GPL) | None | **Study only** | One simple candidate without a new engine: "scatter" and "array along a path" using InstancedMesh, driven by the same structured commands. |
| **BlenderMCP** (MIT) | n0ise already has its own MCP bridge (`tools/mcp`, `AI.md`) with scene, add, set, light, render, export commands | **Research** | Architecture: keep n0ise's structured commands as the one scene format (agents already read, build, render and fix). Added `boolean`. Blender stays an optional external pipeline: agent builds in Blender, exports GLB, imports through `n0_add`. No Blender needed for the core editor. Next commands to add: `group`, `scatter`, `array`, `material` presets. |

## Completed vs not
- **Completed and tested:** Manifold Combine shapes and `boolean` command; BVH picking acceleration with measurement; optional smaller GLB export; saving of combined and sculpted shapes with the project; path trace progress label.
- **Prototype or research only:** TSL, LiteGraph, OSM, Terrain3D, Geometry Nodes, BlenderMCP.
- **Known limits:** redo of an added object; BVH build blocks the page; CDN needed on first use for Manifold and glTF Transform.
